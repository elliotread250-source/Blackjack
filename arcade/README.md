# Open Arcade hub (EMBER//ARCADE design)

The front page of the arcade: `python3 server.py` (stdlib only), Railway service root `arcade/`.

## Layout
- `registry.json` — **the one list of games and tools** (id, name, kind, url, blurb, genres, categories,
  features, featured, pending, artVersion). The page renders every section from it; the server reads it as
  the allowlist for status checks. `id` is the legacy `slug(name)`: play counts are keyed by it, never rename.
- `index.html` — semantic page shell (works before JS: hero and footer are static).
- `css/` — `tokens.css` (colours, type, spacing, motion), `base`, `layout`, `components`, `animations`, `responsive`.
- `js/` — ES modules: `app` (bootstrap), `registry`, `cards`, `sections` (featured, most played, recently
  played, favourites), `library` (search, categories, sort), `search`, `palette` (Ctrl/Cmd+K), `settings`,
  `nav`, `effects` (ambient canvas, parallax, reveals), `hero`, `plays`, `status`, `favourites`, `recent`,
  `suggestions`, `store` (safe localStorage).
- `assets/branding/` — emblem, mark, mono, inverse, wordmark, favicon, apple-touch icon, share image
  (PNG/JPG made from the `*.src.svg` files with macOS Quick Look).
- `assets/game-logos/{id}.svg`, `assets/game-thumbnails/{id}.svg` — original vector art for every entry,
  generated by `tools/art/build.mjs` (sources in `tools/art/`), listed in `assets/manifest.json`.

## Adding a game
1. Add an entry to `registry.json` (copy a similar one; only list `online` in `features` if the game really
   has networked multiplayer — the tests enforce a verified list).
2. Add `LOGOS['id']` to `tools/art/logos.mjs` and `THUMBS['id']` to a `tools/art/thumbs*.mjs`.
3. `node tools/art/build.mjs` (writes the SVGs, the manifest and the registry `artVersion`).
4. `node tests/test_registry.mjs && python3 tests/test_server.py`.
Review art with `tools/art/sheet.html` and `tools/art/view.html?id=…` on a local server.

## Server API (unchanged routes plus status)
- `GET /healthz`, `GET /api/plays`, `POST /api/play {game}` (30 s per visitor+game), `POST /api/suggestions`,
  `POST /api/suggestions/view {code}` (needs `SUGGESTIONS_CODE`), all data on the volume at `DATA_DIR`.
- `GET /api/status` — the server checks each registry URL itself (no redirects, 5 s timeout, 8 at a time,
  cached 90 s, only when the hub is visited) and reports `up` / `down` / `checking`. Nothing in the request
  can change which hosts are contacted.
- `/assets/*` is cached for a day; asset URLs carry `?v=artVersion`, so new art shows immediately.
