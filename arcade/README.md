# Open Arcade hub (EMBER//ARCADE, 20× rebuild)

The front page of the arcade. Run it with `python3 server.py` (stdlib only). The Railway service root is `arcade/`.
It is a static site with no build step and no runtime dependencies: plain ES modules and CSS served as they are.
The design and motion plan is in `docs/arcade-20x/PLAN.md`; what was built and verified is in `docs/arcade-20x/LOG.md`.

## Layout

### `registry.json`
**The one list of games and tools.** Fields: id, name, kind, url, blurb, genres, categories, features, featured, pending and artVersion.
- The page renders every section from it.
- The server reads it as the allowlist for status checks.
- `id` is the legacy `slug(name)`. Play counts are keyed by it, so never rename an id or change a url.

### Pages
- `index.html`: the page shell.
  - It also holds the inline SVG icon sprite and the settings bootstrap, which runs before first paint.
  - Between `<!-- STATIC-LIST:START/END -->` it carries a plain list of every live game. This list works without JS and is hidden once the live library renders.
- `404.html`: the themed GAME OVER page. `server.py` serves it for page 404s; API and /data 404s stay JSON.
- `styleguide.html` with `js/styleguide.js`: the living style guide (tokens, type, buttons, chips, cards, motion demos). It is linked from the footer.

### `css/`
- `tokens.css`: the original colours and fonts (unchanged), plus derived tokens: alpha steps, gradients, glows, z-layers, type scale, durations, easings and staggers.
  - **No new hues.** `tests/test_registry.mjs` fails on any colour outside the original palette.
- `base`, `layout`, `motion`: motion holds the reveal classes and the reduced/off rules.
- `responsive`.
- `components/`: button, chip, card, overlays, misc.
- `sections/`: one file per page section.

### `js/` (ES modules; `app.js` boots each part in isolation, so one failure can't blank the page)
- **Data and state:**
  - `registry`, `plays`, `status`, `store` (safe localStorage);
  - `favourites` (ordered), `recent` (up to 10, with undo);
  - `settings`, `profile` (local stats, streaks and badges);
  - `router` (`#game/{id}`, `#library?cat=&q=&sort=&view=`);
  - `search`, `palette` (Ctrl/Cmd+K), `ambient` (background canvas).
- **`motion/`:** the motion engine.
  - `engine`: one rAF loop, springs, a quality governor and the motion levels from `html[data-anim]` (`full`, `reduced`, `off`).
  - `reveal`, `text`, `count` (count-up and odometer), `pointer` (tilt and magnetic), `flip`, `particles`, `fx`, `marquee`, `scroll`.
  - `sound`: synthesised UI blips, off by default.
- **`components/`:** `card`, `launch`, `sheet` (the detail sheet), `slot` (Surprise me), `toast`, `cursor`, `rocket`, `keys` (shortcuts and the `?` overlay).
- **`sections/`:** one module per section.
  - boot, header, hero, ticker, headliners, continue, charts, vibes, lobby, shelf, library, favourites, profile, idea, footer;
  - `eggs`: the Konami code, "insert coin" and the CONTINUE countdown.

### `assets/`
- `assets/branding/`: emblem, mark, mono, inverse, wordmark, favicon, apple-touch icon and share image.
- `assets/game-logos/{id}.svg` and `assets/game-thumbnails/{id}.svg`: original vector art for every entry.
- `assets/game-moments/{id}.svg`: an original animated "hover moment" for every entry. It uses CSS keyframes inside the SVG, so it animates in a plain `<img>`. It is only loaded on hover or focus in Full motion, and stops under `prefers-reduced-motion`.
- All of these are generated by `tools/art/build.mjs` and listed in `assets/manifest.json`.

## Motion
Settings let you choose Full, Reduced or Off. The default follows `prefers-reduced-motion`.
- **Reduced** removes keyframe animations and keeps opacity and colour transitions.
- **Off** removes everything.
- **Quality governor:** drops effects step by step if the frame rate stays below 50 fps (28 on touch devices).
- **Background effects:** a separate switch; Off stops the canvas.
- **Reveals:** only arm once the scripts have loaded (`html.motion-ready`), so content is never hidden by a failed script.

## Adding a game
1. **Registry:** add an entry to `registry.json` (copy a similar one).
   - Only list `online` in `features` if the game really has networked multiplayer; the tests enforce a verified list.
2. **Logo and thumbnail:** add `LOGOS['id']` to `tools/art/logos.mjs` and `THUMBS['id']` to a `tools/art/thumbs*.mjs`.
3. **Hover moment:** add `MOMENTS['id']` to `tools/art/moments.mjs`.
   - Use `frame(css, body)`. The body draws into a 204×136 window; keep it small and original, using brand colours or the game's own palette.
   - `build.mjs` refuses to run if a moment is missing.
4. **Build the art:** `node tools/art/build.mjs` writes the SVGs, the manifest and the registry `artVersion`.
5. **No-JS list:** `node tools/static-list.mjs` refreshes the list in `index.html`. The tests check it is in sync.
6. **Tests:** `node tests/test_registry.mjs && python3 tests/test_server.py`. Optionally also `node ../tools/e2e/hub.mjs` with a local server on :8084.

Review art with `tools/art/sheet.html` and `tools/art/view.html?id=…` on a local server.

## Server API (unchanged routes plus status)
- `GET /healthz`, `GET /api/plays`, `POST /api/play {game}` (30 s per visitor+game), `POST /api/suggestions`,
  `POST /api/suggestions/view {code}` (needs `SUGGESTIONS_CODE`), all data on the volume at `DATA_DIR`.
- `GET /api/status` — the server checks each registry URL itself (no redirects, 5 s timeout, 8 at a time,
  cached 90 s, only when the hub is visited) and reports `up` / `down` / `checking`. Nothing in the request
  can change which hosts are contacted.
- `/assets/*` is cached for a day; asset URLs carry `?v=artVersion`, so new art shows immediately.
- Any other unknown page (GET/HEAD) gets the themed `404.html` with status 404; `/api/*` and `/data` 404s stay JSON.
